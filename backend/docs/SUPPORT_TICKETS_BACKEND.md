# Звернення в підтримку (Backend)

## Навіщо це

Користувач заповнює форму на сторінці підтримки сайту. Сервер зберігає звернення в базі, показує його в **Django Admin**, за потреби додає **лист співробітникам** (якщо налаштована пошта). З фронту **не приймаються** статус, пріоритет, id користувача чи інші службові поля — їх виставляє лише сервер або адмінка.

## Де лежить код

| Що | Де |
|----|-----|
| Додаток | `apps/support/` |
| Моделі | `apps/support/models.py` — `SupportTicket`, `SupportTicketAttachment`, `SupportTicketStatusHistory` |
| Створення тикета | `apps/support/api/views.py` — `SupportTicketCreateView` |
| Валідація полів форми | `apps/support/api/serializers.py` — `SupportTicketCreateSerializer` |
| Листи, файли, дедуп, IP | `apps/support/services.py` |
| Сигнали (номер тикета + історія статусу) | `apps/support/signals.py` |
| Адмінка | `apps/support/admin.py` |
| Підключення сигналів | `apps/support/apps.py` → `ready()` імпортує `signals` |

## URL API

У кореневому роутері `apps/api/urls.py` підключено `path('support/', include('apps.support.api.urls'))`.

- **POST** `/api/support/tickets/` — створити звернення (єдиний публічний метод для форми).

Детальний роут: `apps/support/api/urls.py` → `tickets/`.

## Що можна передати в POST (тіло)

| Поле | Опис |
|------|------|
| `category` | Код категорії: `technical`, `payment`, `content`, `account`, `other` |
| `subject` | Коротка тема (після очищення — мін. 3 символи) |
| `message` | Текст (мін. 20 символів). Очищення в `SupportTicketCreateSerializer` → `_sanitize_message_text()`: прибираються нуль-байти та фрагменти на кшталт HTML-тегів, `\r` нормалізується до `\n`, у межах кожного рядка послідовності пробілів/табів стискаються до одного пробілу, на початку й у кінці кожного рядка пробіли/таби знімаються, **три й більше порожніх рядків підряд** зводяться до **двох** переносів; після цього весь текст ще раз `strip()`; довжина обрізається до ліміту поля |
| `name` | Для **гостя** — обов’язково ім’я/нік |
| `email` | Для **гостя** — обов’язково |
| `website` | Honeypot: має бути порожнім |
| `page_url` | Необов’язково, адреса сторінки з браузера (до 500 символів) |
| `attachments` | Необов’язково, **multipart**: кілька файлів під одним ім’ем поля (див. ліміти нижче) |

Якщо в запиті є **валідний JWT** (`Authorization: Bearer …`), користувач вважається авторизованим: **email і нік беруться з облікового запису** (`user.email`, `user.username`), поля `name`/`email` з тіла для контактів **не використовуються**. Якщо в профілі немає email — **400** з поясненням.

## Що сервер додає сам

Під час збереження тикета заповнюються (клієнт цього змінити не може):

- зв’язок `user` (або порожньо для гостя);
- `name`, `email` (для залогіненого — з акаунта);
- `status` = новий, `priority` = звичайний, `source` = `support_page`;
- `ip_address`, `user_agent`, `http_referer`, `submitted_page_url`;
- `ticket_number` після першого збереження (формат на кшталт `FV-2026-000042`) — через сигнал `post_save` у `signals.py`.

## Вкладення (файли)

Логіка в `services.save_attachments()`:

- **Не більше 3** файлів за один запит; якщо більше — помилка, нічого не «обрізається» мовчки.
- До **5 МБ** на файл.
- Дозволені типи за розширенням: `.pdf`, `.jpg`, `.jpeg`, `.png`, `.webp`.
- Додатково перевіряються **перші байти файлу** (щоб не підійшов файл з чужим розширенням) і **Content-Type**, якщо він заданий і не `application/octet-stream`.
- На диску ім’я файлу **випадкове (UUID)**; оригінальна назва — у полі `original_name`. Шлях задає `upload_to` у моделі вкладення (папки за рік/місяць).

Помилки вкладень повертаються як **400** з тілом на кшталт `{"attachments": ["текст помилки"]}`.

## Безпека та стійкість до зловживань

- **CSRF**: на view навішано `csrf_protect`; фронт має слати заголовок `X-CSRFToken` (як і для інших небезпечних запитів).
- **Throttling**: `ScopedRateThrottle`, scope `support_ticket`. У `FanVers_project/settings.py` у `REST_FRAMEWORK['DEFAULT_THROTTLE_RATES']` для ключа `'support_ticket'` задано значення `'10/hour'` (його можна змінити в тому ж файлі). Залогінений обмежується за **id користувача**, гість — за IP.
- **Дедуплікація**: однаковий email + той самий текст повідомлення протягом короткого вікна (кеш) — **429**; мітка в кеші ставиться **лише після успішного коміту** транзакції, разом із відправкою листа в `on_commit`.
- Транзакція: тикет і вкладення зберігаються в одній `atomic()`; при помилці файли з диска прибирає `delete_attachment_files()`.

## Лист співробітникам

`notify_staff_new_ticket()` у `services.py` надсилає лист активним користувачам з прапором **staff або superuser** і непорожнім email. Виклик після коміту — у **окремому потоці**, щоб повільний SMTP не затримував HTTP-відповідь. Якщо пошта не налаштована, запис у БД усе одно лишається; помилки — у логах.

## Відповідь при успіху

**201 Created**, приклад:

```json
{
  "ticket_number": "FV-2026-000042",
  "message": "Звернення успішно надіслано. Ми зв'яжемося з вами на вказаний email."
}
```

## Медіа

У `FanVers_project/settings.py` задані `MEDIA_URL` і `MEDIA_ROOT` (типово `/media/` і каталог `media` відносно `BASE_DIR`). Збережені вкладення потрапляють туди згідно з `upload_to`. У продакшені потрібна **роздача** `/media/` веб-сервером або іншим шаром.

## Міграції

У репозиторії є початкова міграція `apps/support/migrations/0001_initial.py`. Після оновлення коду на середовищі виконайте `python manage.py migrate` (або `migrate support`, якщо потрібно лише цей додаток).
