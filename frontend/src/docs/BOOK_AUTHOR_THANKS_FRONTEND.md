# Подяка власнику книги (FanCoins) — фронтенд

Коротко: на **сторінці книги** у блоці з іконкою та підписом на кшталт «Подякувати автору» / «Подякувати перекладачу» читач може відкрити **модалку**, ввести суму в FanCoins і підтвердити. Гроші йдуть на баланс **власника книги** згідно з бекендом; **власник своєї** книги цей блок бачить **без кліку** (лише оформлення).

---

## 1. Де що лежить у коді

| Файл | Роль |
|------|------|
| `catalog/sections/BookHero.tsx` | Блок подяки: кнопка для читача, перехід у модалку або **модалка входу**; для власника — статичний вигляд без дії. |
| `catalog/ModalThankAuthor.tsx` + `ModalThankAuthor.module.css` | Модалка: текст, ліміти сум, поле вводу, баланс з `useAuth`, відправка. |
| `api/authorThanksApi.ts` | `POST` на ендпоінт подяки з полями, які очікує бекенд. |
| `api/endpoints.ts` | **`API.authorThanks`**, **`API.chapterProgress`**, **`API.readingStats`** (секция monitoring). |
| `api/monitoringApi.ts` | Прогрес читання и stats — **READING_PROGRESS_FRONTEND.md**. |
| `api/http.ts` | Спільний клієнт: **Bearer**, **CSRF** для POST, повтор після refresh при 401. |
| `catalog/BookDetailReader.tsx` | Передає в `BookHero` підпис залежно від типу книги, **`thankAuthorInteractive={true}`**, `bookId`, тощо. |
| `catalog/BookDetailOwner.tsx` | **`thankAuthorInteractive={false}`** — не подякувати самому собі через UI. |
| `auth/AuthModalContext.tsx` | **`openLoginModal(path)`** — якщо натиснули подяку без сесії. |
| `auth/service.ts` | **`refreshAuthStatus()`** після успішної подяки — оновити баланс у store. |

## 2. Потік для читача

1. Натискання на блок подяки (коли є **`bookId`** і **`thankAuthorInteractive`**).
2. Якщо **не залогінений** — відкривається **вхід**, з поверненням на поточний шлях (`useLocation().pathname`).
3. Якщо залогінений — відкривається **`ModalThankAuthor`**.
4. При **відкритті** модалки генерується новий **`idempotency_key`** (UUID), щоб повтор відправки після обриву мережі з **тим самим відкриттям** не подвоїв списання на сервері.
5. Перед відправкою: перевірка суми на клієнті (**мінімум 20**, **максимум 10 000**, до двох знаків після коми), перевірка **`bookId`**; **опційно** — порівняння з балансом з **`useAuth`** (це лише зручність: баланс у вкладці може встигнути змінитись, остаточне рішення **завжди на сервері**).
6. **`sendAuthorThanks`** → після успіху **`refreshAuthStatus()`**, toast, закриття модалки.
7. Помилки з API показуються через **`extractUserMessage`** і спільний провайдер нотифікацій.

Поле **`message`** у API передбачене, але **поточна модалка його не надсилає**.

---

## 3. Текст і підписи

- Заголовок модалки й абзаци в **`ModalThankAuthor`** українською; перший абзац пояснює підтримку власника (автор оригіналу або перекладач).
- Окремий абзац про **мінімальну та максимальну** суму синхронізований з константами у файлі (їх варто тримати узгодженими з бекендом при зміні лімітів).
- На обкладинці в блоці подяки показується число з пропса **`thankAuthorCoins`** (типово **20** як орієнтир мінімуму), підпис — **`thankAuthorLabel`** (для перекладу — «Подякувати перекладачу»).

---

## 4. Доступність і розмітка

- Інтерактивний блок у **`BookHero`** — це **`button type="button"`** з **`aria-label`**, стилі кліку в **`BookDetail.module.css`** (`.thankAuthorInteractive`).
- Мітка **«Авторська книга»** у колонці героя показується **тільки якщо** з батьків передано непорожній **`authorMarkText`** — для перекладів без тексту заглушка «Авторська книга» **не** показується.

---

## 5. Бекенд (куди стукаємо)

- **Метод і шлях:** `POST /api/monitoring/thanks/`
- **Тіло:** `book_id`, `amount` (рядок з двома знаками, напр. `"50.00"`), `idempotency_key`; опційно `message`.

Детальна поведінка, помилки, транзакції та обмеження частоти — у **`backend/docs/BOOK_AUTHOR_THANKS_BACKEND.md`**.
